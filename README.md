# ECHO-UNIT / Fleet Control

Учебная локальная система для управления автопарком: грузовики, рейсы, сотрудники, предупреждения и GPS-симулятор.

**Технологии:** FastAPI, PostgreSQL (psycopg), HTML, CSS, JavaScript и Leaflet.

**Важно:** GPS-координаты учебные. Линии между городами схематические, это не реальные автомобильные дороги. Приложение запускается на компьютере пользователя, а публикация кода на GitHub сама по себе не размещает сайт в интернете.

## Что умеет приложение

- Администратор управляет машинами, рейсами и доступом сотрудников.
- Диспетчер работает с доступными ему разделами, но не может самостоятельно назначить себе права администратора.
- Регистрация нового сотрудника создаёт заявку: войти можно только после одобрения администратором.
- Рейсы имеют статусы «Запланирован», «В пути», «Завершён». Изменение рейса и грузовика выполняется в транзакции PostgreSQL.
- GPS-симулятор присылает тестовые координаты активных рейсов через защищённый локальный API. Без симулятора сайт тоже работает.
- Карта использует Leaflet и загружаемые из интернета изображения OpenStreetMap: для отображения карты нужен доступ к соответствующим ресурсам.

## Перед запуском

Нужны Python, PostgreSQL и VS Code (или другой редактор). Команды ниже приведены для терминала macOS.

Откройте **корень проекта** — папку, где находятся `main.py` и `requirements.txt`.

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
cp .env.example .env
```

В `.env` укажите настройки **своей** базы:

```dotenv
TRUCKS_DB_HOST=localhost
TRUCKS_DB_PORT=5432
TRUCKS_DB_NAME=fleet_demo_local
TRUCKS_DB_USER=postgres
# TRUCKS_DB_PASSWORD=ваш_локальный_пароль
```

Раскомментируйте `TRUCKS_DB_PASSWORD` и введите пароль, если не хотите отвечать на запрос пароля в терминале. В GitHub загружается `.env.example`, **не `.env`**.

### Вариант А. У вас уже есть рабочая база

1. Остановите прежний сервер и симулятор (`Control + C`). Сделайте резервную копию базы в pgAdmin.
2. В `.env` укажите параметры **существующей** базы. Если рабочая база называется `trucks_mko`, укажите именно это имя.
3. Выполните проверку:

   ```bash
   python check_setup.py
   ```

4. Если проверка прошла, запустите приложение:

   ```bash
   python main.py
   ```

5. Откройте <http://127.0.0.1:8000> и войдите с существующей учётной записью.

**Нельзя:** выполнять `sql/install_new.sql` в рабочей базе. Этот SQL предназначен только для новой пустой базы и не обновляет существующую структуру. Если `check_setup.py` обнаружил ошибку, сначала проверьте параметры подключения и сделайте резервную копию; не запускайте SQL установки наугад.

Если `SESSION_SECRET_KEY` или файл `.session_secret` поменялся, старые сессии станут недействительными: нужно будет войти заново. На данные PostgreSQL это не влияет.

### Вариант Б. Создать отдельную пустую учебную базу

1. В pgAdmin создайте **новую пустую** базу, например `fleet_demo_local`. Не удаляйте и не пересоздавайте `trucks_mko`.
2. Откройте Query Tool именно в `fleet_demo_local` и до запуска SQL проверьте:

   ```sql
   SELECT current_database();
   ```

   Ответ должен быть `fleet_demo_local`.
3. Выполните содержимое `sql/install_new.sql` **только в этой новой базе**. Скрипт откажется работать, если таблицы Fleet уже существуют.
4. В `.env` задайте `TRUCKS_DB_NAME=fleet_demo_local` и другие параметры подключения.
5. В терминале корня проекта выполните:

   ```bash
   python check_setup.py
   python create_admin.py
   python main.py
   ```

   `create_admin.py` нужен только для первого администратора в новой базе. Если администратор уже существует, команда откажется создавать другого.
6. Откройте <http://127.0.0.1:8000>, войдите и создайте грузовик и рейс.

## GPS-симулятор

Войдите в приложение, создайте рейс для поддерживаемых учебных городов и переведите его в статус «В пути». Откройте **второй** терминал в том же корне проекта:

```bash
source .venv/bin/activate
python gps_simulator.py --all
```

По умолчанию движение ускорено в 60 раз. Для изменения скорости учебной симуляции:

```bash
python gps_simulator.py --all --time-scale 1
```

Остановка: `Control + C`. Симулятор использует тот же локальный GPS-токен, что и сервер; если он запущен из другой копии проекта, токены могут отличаться. Не публикуйте `.gps_token` и `.session_secret`.

## API и простые проверки

После запуска доступна документация FastAPI: <http://127.0.0.1:8000/docs> и <http://127.0.0.1:8000/redoc>. Документация показывает адреса API, но сама по себе не снимает ограничения авторизации и CSRF.

Проверить, что Python-файлы читаются без синтаксических ошибок, можно командами:

```bash
python -m py_compile main.py config.py create_admin.py check_setup.py gps_simulator.py
python -m compileall -q fleet
```

Если установлен Node.js, можно дополнительно проверить синтаксис JavaScript-модулей:

```bash
for file in static/js/*.js; do node --input-type=module --check < "$file"; done
```

Это **проверка синтаксиса, а не проверка всех функций**. Основные действия на сайте нужно проверять вручную с отдельной тестовой базой: вход, права ролей, создание машины, запуск и завершение рейса, учебный GPS и обновление карты.

## Перед GitHub

В репозиторий отправляются исходный код, HTML, CSS, JavaScript, `requirements.txt`, README, `.gitignore`, `.env.example` и `sql/install_new.sql`.

Не публикуйте `.env`, `.session_secret`, `.gps_token`, `.venv`, резервные копии PostgreSQL и другие локальные секреты. Проверьте `git status` и список `git diff --cached --name-only` **перед коммитом**. Если секреты уже были закоммичены, исключения в `.gitignore` недостаточно: секреты нужно заменить и проверить историю Git.
